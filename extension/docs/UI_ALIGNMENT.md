## 按新需求替换的行为

| 上一版 | v1.3.0 |
| --- | --- |
| 长画布和最小 24px 间隔 | 永远一屏高，间距随消息数压缩 |
| 内部滚动和外部拖动滑块 | 不创建滑块，overflow: clip，无内部滚动范围 |

| 搜索后把轨道变成搜索结果 | 搜索仅影响目录，右侧首尾保持不变 |

## 布局公式

令轨道高度 H，端点内边距 p = min(16, H/2)，消息数 n。n > 1 时，第 i 条消息（0 开始）的归一化顺序为 t = i/(n-1)。

`crowding = max(1, (n-1)*24/max(1,H-2p))`

`exponent = 1 + min(1, log2(crowding)*0.32)`

`y(i) = p + t^exponent * (H-2p)`

因此首条固定在 p，末条固定在 H-p；消息多时 exponent 增加，使上方旧节点更密而下方近期节点保留更多间距。没有任何按消息数拉长内容画布的代码。

普通圆点直径最大 12px，密集时按邻距缩小到至少 2.5px；活动/键盘聚焦节点保留至少 7px 的视觉提示。每条消息仍然拥有独立节点，没有合并组。

非常密集时圆点可能相互重叠，有限像素无法保证全部分离。鼠标通过最近 y 坐标选择节点，键盘 ↑/↓、Home/End 和目录搜索用于精确逐条选择。

本版不再进行“与上游长画布 0 像素差异”的断言。测试应验证用户的新布局要求，而不是把新布局伪称为原版一模一样。
