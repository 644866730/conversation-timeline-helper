# 兼容性与边界 · v1.4.1

> 以下说明继承自 v1.4.1；v1.4.2 新增预览位置保护，详见 [PREVIEW_FIX.md](PREVIEW_FIX.md)。

## 安装与网页识别

Manifest V3，最低清单要求 Chrome 120。只注入 `chatgpt.com` 和 `chat.openai.com` 的顶层页面，设置权限仍只有 storage。MAIN 助手是 1.4.0 引入的静态内容脚本，升级需要重载扩展并刷新标签页。

DOM 识别保留新旧结构：data-message-author-role、data-turn、data-turn-key、data-content-search-unit-key、用户气泡以及稳定消息 ID。虚拟列表导航还记录 data-index / data-item-index / data-virtual-index 和实际 turn key。

这些属性是兼容性观察，不是 OpenAI 提供的稳定扩展协议。账号灰度变动可能影响识别或定位。

## 顺序与显示

使用重叠稳定标识作为前后顺序锚点，保留本页观察过但暂未挂载的消息。完全不重叠且没有全局位置提示时，按滚动方向推断；没有稳定 ID、重复正文、局部序号重用时不保证绝对无误。诊断记录 inferredOrderBatches。

轨道首尾按“显示范围”计算：只看提问时为最旧/最新的已加载提问；双方消息时覆盖已观察双方。搜索筛选不改变轨道。

## 点击后的定位顺序

1. 重新扫描：已经挂载则直接对齐，避免使用被 React 重用的过时 DOM 引用。
2. 可选原生虚拟列表：MAIN 助手仅在本次请求中进行有限的描述符检查，尝试 scrollToIndex / scrollToItem，以实际 key 为主。记录索引仅在当前挂载锚点校准一致时作为辅助，不凭消息序号猜真实列表索引。
3. 原生助手不可用时，用记录的滚动位置尝试一次，再按当前实际消息标识与目标顺序逐步移动原会话滚动容器，等网页正常换页。
4. 找到目标后检查真实 DOM 和可见范围，进行有限布局校准。助手返回“已调用”不等于完成；错误的私有定位方法不能造成虚假的成功提示。

不为了导航而重新加载整个网站、不构造带猜测参数的 URL、不请求账号 API、不打开其他对话或修改网页 React 状态。失败不弹缓存正文。

## 中止与原生加载

单次定位上限为 60 秒 / 320 步，连续无进展约 8 秒停止；原生网络较慢或错误可点击重试。首次点击后可能需要逐页等待，不保证瞬间跳到非常早的消息。

鼠标滚轮、触屏/网页点击、Esc、取消、另一个目标、切换会话、页面隐藏、关闭扩展、重建索引会取消旧定位。取消停止的是扩展后续动作；ChatGPT 已经发出的原生请求可能仍会完成。

## 分支、删除和刷新

不恢复隐藏分支、已删除消息和跨刷新缓存。页面同一 URL 下改变分支后，旧索引可能仍含之前观察过的节点，定位可能找不到它；这时重建索引可清除旧节点，不操作聊天本身。

## 验证边界

本次可用环境没有登录的真实 ChatGPT 账号。新测试使用 Chromium 真正的 MAIN / ISOLATED JavaScript 环境隔离、原生滚动事件和本地分页/虚拟列表；聊天 DOM、React 入口和 Chrome 存储/消息 API 是测试模拟，不是网站生产代码或真实扩展安装验收。不要把模拟测试通过当作所有账号已经实测。
