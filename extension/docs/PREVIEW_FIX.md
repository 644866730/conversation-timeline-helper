# v1.4.2 图片 / 附件预览位置保护

## 问题与证据

用户反馈：打开聊天附件中的图片，关闭预览后，页面回到很早的对话位置。
用户截图只包含附件列表，没有提供运行时 DOM、事件日志和关闭瞬间的滚动轨迹。
因此，不能据此唯一判定该账号的触发原因。

在保留的 v1.4.1 源码中发现时间轴 host 固定使用很高的 z-index，并且没有页面预览弹层保护。
本地 Chromium 中复现了两个缺口：

- 将原生预览关闭按钮放到早期时间轴节点的区域，点击被时间轴截获。
- 模拟关闭预览时原生焦点返回旧附件，scrollTop 从 13885 变为 436，旧版不会恢复阅读位置。

基线 JSON：`../tests/results/preview-baseline-results.json`。
第二项是模拟网页自身执行 focus 的结果，并不是发现扩展主动调用旧附件的 focus。
两个基线用例用于说明实现缺口，不声称与用户账号 DOM 完全相同。

## 修复机制

`src/preview-guard.js` 在隔离世界工作，识别可见 dialog / aria-modal、原生 dialog、媒体全屏及页面显式滚动锁。
它不把普通 overflow:hidden 当作预览信号，以免误判 ChatGPT 的应用布局。
也不会因为无关的隐藏 main 而暂停仍在阅读的对话。

在打开前的点击/键盘事件中保存真实阅读锚点、视口偏移和滚动框架；不是保存上次点击的时间轴节点。
预览打开后，扩展自己的 Shadow host 被隐藏且设为 inert，暂停目录扫描、当前节点更新、快捷键与导航任务。
网页自己的弹层、焦点恢复、原生滚动锁及原型方法均不被改写。

预览关闭后，优先以稳定消息标识重新找到阅读锚点，再恢复它在视口中的原位置。
仅在没有可用锚点、原滚动根仍存在且完整滚动高度未变时，尝试使用原坐标框架的检查点。
若目标坐标超出当前滚动范围则跳过，绝不根据某个旧序号调用时间轴跳转。
未漂移时不写 scrollTop；发生漂移时使用即时校正，不做平滑“跳回”动画。
检查窗口最长约 1 秒，并对窗口内的滚动漂移安排下一帧检查。

新手动输入、切换会话、禁用和销毁都会取消校正。嵌套弹层共用同一个阅读检查点。
MAIN 世界助手同时拒绝弹层期间残留的定位请求。主动节点导航仍沿用 v1.4.0 的有界、DOM 校验机制。
另修正了页面级时间轴快捷键被“手动滚动取消”监听器在同一个事件中误取消的问题。

## 边界

这不是浏览器级滚动锁，也不会无限追踪或拦截网站的所有焦点操作。
未知弹层、超出校正窗口的原生异步跳转、整个会话结构被替换或网站异常仍可能影响结果。
没有与后台会话接口通信，没有因为图片预览而调用历史分页按钮或虚拟列表 seek。
不保证完全未知的虚拟化坐标框架能恢复；错误时不能以缓存正文弹窗冒充原消息位置。
